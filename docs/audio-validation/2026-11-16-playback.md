# Workout sound investigation

## Report

On November16 the user reported missing transition, side-switch, rest,
countdown and finish audio on an iPhone. Disabling phone silent mode restored
some sound, but did not settle the inconsistent-finish report.

## Confirmed code defects addressed

- A rejected/failed recorded clip previously returned success, suppressing the
  intended device-speech fallback. Failures now return false; deliberate
  cancellation remains handled, without starting stale fallback.
- Interrupting a clip left its Promise unsettled. Stop now settles it and clears
  handlers, while canceling a pending manifest prevents later stale playback.
- Delayed fallback could arrive after pause, exit or a newer announcement.
  Speech generations now guard those callbacks. Countdown-only cues do not
  cancel a pending announcement.
- Resume now unlocks audio again; countdown/finish signals attempt to resume an
  interrupted audio context rather than silently scheduling into suspension.

## Browser session evidence

`2026-11-16-session.json` records a real-time42-second local browser run using the
actual coach, cues and machine modules. Fixture: prepare6s, left8s, switch6s,
right8s, rest6s, final8s. No autoplay-policy bypass. Recorded clip events reached
playing and ended; deliberately uncovered8-second target announcements reached
Korean device-speech start. Countdown oscillators used a running context. The
final three-tone signal was scheduled and the finish recording ended at3.4s.
The empty speech primer is interrupted when the first real cue starts; it is not
a missing user-facing announcement.

This is desktop browser evidence, not an iPhone hardware/silent-switch test.
It does not prove speaker output on the user's phone. The final clip was not
canceled by the simulated finish transition.

## Countdown history

All revisions of cues.ts, including initial f6a1d27 (October18), specify3/2/1.
No removal of5/4 was found. The user's remembered five-second countdown differs;
these changes do not claim to restore a five-second countdown.

## iPhone routing candidate

Web Audio defaults to ambient whereas HTML media defaults to playback. In silent
mode, sounds can differ as clips start/end. Explicit AudioSession playback is a
supported-browser candidate, but may pause other music. It needs the requested
product choice and separate iPhone validation, not an audio-engine migration.

- https://bugs.webkit.org/show_bug.cgi?id=237322
- https://developer.mozilla.org/en-US/docs/Web/API/AudioSession/type
- https://developer.mozilla.org/en-US/docs/Web/API/Audio_Session_API

## User decision14:03:56

Other music must not stop: the user may listen to music while exercising.
Do not select exclusive playback by default or treat this as approval for an
opt-in setting. No silent-media-loop workaround is applied. Mixed routing stays
unchanged. Silent-mode behavior on the iPhone remains an open limitation;
the independent failure/cancel/resume fixes do not claim to solve that routing.
